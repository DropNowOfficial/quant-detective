## 1. run_all.sh false success
* Cause: the script ended with `cp ...; exit "${PIPESTATUS[0]}"`. `PIPESTATUS` then described the last `cp` (status 0), not the `{...} | tee` pipeline, so a failed verification step was reported as success.
* Fix: `set -uo pipefail`; pipeline status captured on the very next line; copies only when the source exists and a failed copy also fails the run; any failing step keeps all later steps running (complete log) but the final exit is non-zero (`RUN_ALL_FAILED` line).
* Test: `tests/test_run_all_exit_status_20261011.py` runs a temp copy of `run_all.sh` with stub steps (failing `verify_inputs`, succeeding copy) and asserts non-zero. Before: 3 of 4 tests failed (`audit14_tests_before.txt`, commit `5ad9691`, e.g. "FALSE SUCCESS: verify_inputs failed but run_all.sh exited 0"). After: all pass (`audit14_tests_after.txt`).
* `verify_inputs.py` review: all comparison failures append to `fails` and exit 1; missing files raise (non-zero); a date-set mismatch records a failure and continues. No exit-0-on-mismatch path was found. Change made: the price section no longer relies on a tracked CSV (see 4); the Yahoo byte mismatch with value fallback stays but is now printed as `DAILY_CSV_SHA256_MISMATCH` with the exact tolerated conditions. Probe (`audit14_verify_inputs_tamper_probe.txt`): corrupting one manifest hash makes `verify_inputs.py` print `VERIFY_INPUTS_FAIL` and exit 1.

## 2. `later_restatement` did not filter by time
* Before: any differing value in any other filing was flagged, including OLDER filings. The only flagged row (JNJ FY2023 GrossProfit in filing `0000200406-25-000038`, filed 2025-02-13) pointed at the 2023 filing `0000200406-23-000016` (filed 2023-02-16, value 63,854,000,000).
* Fix: `extract.classify_other_filings`. Same tag/unit/start/end only (the lookup key). `later_filed_value_difference` = other filings with a strictly later public filing date and a different value; `earlier_or_same_day_value_difference` = the rest (older or same-day). Granularity is the filing DATE (companyfacts has no acceptance time for other filings), so same-day filings are not ordered. Neither field implies restatement and an empty field does not imply none. Reports no longer infer 'no restatement'. Input order does not matter.
* Result after regenerating `data_points.csv`: 0 rows with a later-filed difference; 1 row (the context row above) with an earlier-filed difference. `results.json` is unchanged (byte-identical).
* Tests: `tests/test_later_filing_flag_20261011.py` (synthetic 2023 vs 2025 case, same-day, same value, order independence, CSV columns, report wording). Before: 8 failed; after: pass.
