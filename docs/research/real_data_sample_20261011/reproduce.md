# Reproducing the real-data sample (SEC GP/A + Sloan inputs, Yahoo/Nasdaq prices for MAX)

Raw data is **not** in Git (AGENTS.md rule 6). Everything below downloads it into untracked
directories (`_raw/`, `_out/`, both git-ignored), records retrieval times and SHA256, compares with the
committed manifests, recomputes with the fixed code, and compares values.
This sample proves traceability and recomputability of inputs only. It makes no claim of investment validity.

## One command

```bash
cd <repo>                      # branch research/new-factors-20261011-main-only
uv sync --frozen --extra research
bash docs/research/real_data_sample_20261011/run_all.sh [LOGDIR]
```

Needs outbound HTTPS to `data.sec.gov`, `www.sec.gov`, `query1.finance.yahoo.com`, `api.nasdaq.com`.
No keys, no logins. SEC requests use `User-Agent: QuantDetective research contact-research@example.com`
and stay below 4 requests/second. Nothing here touches credentials, live trading or production.
Exit code 0 only if every comparison passes. Log goes to `LOGDIR/run.log` (default `reproduce_run_<UTC date>/`).

## Steps (what `run_all.sh` does)

| # | Script | What it does | Pass criterion |
|---|---|---|---|
| 1 | `fetch_all.py --out _raw` | Downloads SEC submissions + companyfacts (AAPL, JNJ, ADBE), filing index pages, `.hdr.sgml`, R pages (face statements + AAPL note R50/R49), Yahoo chart JSON and Nasdaq historical JSON for **2026-07-01..2026-10-09**; writes `_raw/retrieval_log.json` (URL, retrieval time UTC, SHA256, expected SHA256, MATCH/MISMATCH). | all fetched |
| 2 | `extract.py` | Rebuilds `data_points.csv` from `_raw/` (acceptance time from the filing index page, cross-checked with hdr). | rebuilt file byte-identical to committed `data_points.csv` |
| 3 | `recompute.py` | GP/A and Sloan from the rebuilt CSV (stdlib only). | `results.json` identical to committed |
| 4 | `max_prices.py` | MAX with `factor_candidates.max_lottery(calendar_tz="America/New_York")` on the fresh prices; asserts equality with an independent standalone computation and invariance across UTC/NY/Tokyo/Auckland spellings of the same instant. | no assertion error |
| 5 | `verify_inputs.py` | Re-fetch comparison: every `data_points.csv` value vs fresh companyfacts (exact); R-page values (exact); acceptance times (index, hdr, submissions); prices (hash, then tolerance fallback); MAX baseline vs fresh. | `VERIFY_INPUTS_OK` |
| 6 | `crosscheck_repo_code.py` | Feeds the CSV into the repo's `gross_profitability` / `sloan_accruals` and compares with step 3. | `CROSSCHECK_OK` |

## Hash manifests and what a MISMATCH means

* `SHA256SUMS.txt` — hashes of the **originally used** raw files (retrieved 2026-10-11 ~07:51–07:56 ET), incl. original `yahoo_*.json` and `nasdaq_*.json`.
* `SHA256SUMS_audit_20261011.txt` — hashes of the files added by the audit (index pages, hdr, `FilingSummary.xml`, AAPL R49/R50).
* `fetch_all.py` prints per file `MATCH`, `MISMATCH`, or `NO_EXPECTED_HASH`.
* **SEC files** (submissions, companyfacts, R pages, index pages) are expected to be byte-identical while the filings are unchanged. Submissions/companyfacts are regenerated by the SEC and grow with new filings; a `MISMATCH` there is possible later and is then judged by step 5 (exact value comparison of every used fact).
* **Yahoo JSON legitimately differs** on re-download (the `meta` block carries live quote fields; adjusted close can be revised after later dividends/corrections; the exact original request URL was not recorded, so the same window is requested with `period1/period2`). On `MISMATCH`, `verify_inputs.py` says so explicitly and compares the **computed values** with the originally used `daily_<TICKER>.csv`: dates identical, raw close within $0.005, adjusted close relative diff ≤ 1e-6 and daily returns ≤ 1e-4 absolute (tunable `--adj-rel-tol`, `--ret-tol`), and MAX values within `--ret-tol`. These tolerances are choices of this procedure, not vendor guarantees; a result outside them fails the run.
* Nasdaq JSON is a second source for the **raw close only** (no adjusted close), checked within $0.005.

## Provenance and limits

* Adjusted-close convention is Yahoo's (split + dividend adjusted), observed not documented; Stooq (documented) was blocked by a JS challenge and not bypassed.
* `known_at` for price rows in `max_prices.py` is assumed to be the 16:00 ET session close; real vendor publication times are unknown, so this is not point-in-time evidence.
* Financial inputs come from `companyfacts` (an SEC-derived view) cross-checked against rendered R pages; primary iXBRL documents are not hashed.
* Sloan remains NOT usable for scoring: the Compustat-item → XBRL-tag mapping is unverified.
